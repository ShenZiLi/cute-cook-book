# 技术设计

## 技术栈

- React + TypeScript + Vite：手机单页网页，两个主要路由（首页、菜谱详情）。
- React Router：浏览器前进／返回与详情深链接按网页习惯工作，部署时需提供单页路由回退。
- CSS 设计变量、响应式布局、原创内联 SVG 食材／锅具／动作元素，CSS 关键帧驱动短循环；完整演示复用各步骤画面按时间轴串联。系统请求减少动态效果时使用静态关键帧。
- React 组件状态配合集中 reducer；菜谱为类型化静态数据，数量与单位只在一处定义。
- 少量设置、步骤进度和计时结束时刻存在 localStorage；照片 Blob 存在 IndexedDB。存储失败显式反馈。
- TypeScript 类型检查、生产构建、关键状态规则的 Vitest 测试、手机视口的手动浏览器检查。

## 边界与数据流

`recipe data → total ingredients / stage navigation / step card / animation scene`。数据模型将总量和分步加入量关联到同一食材 ID，并区分备菜处理、首次加入锅中和回锅复用。总量只按首次实际加入量汇总；备菜与回锅节点仍显示该份食材的用量，但不重复计入。量勺文字由菜谱提供经校准的约值，不做跨调料通用密度换算。完成标志和下一步预告也来自节点数据。

`user action → reducer → persisted progress`。查看节点与推进节点是不同动作，前者只改变 inspected step，后者标记 completion 并改变 active step。阶段切换与演示播放不修改完成记录。

`timer action → target end timestamp → derived remaining`。自动计时开关在首个计时节点之前即可操作，才能让用户从第 03 步进入第 04 步时自动启动。倒计时只保存目标结束时刻和所属节点；前台刷新显示，页面重新可见或重新加载时立即重算。后台无需持续运行定时器，也不请求通知权限。切换自动计时设置不修改正在运行的计时。

`file input → type/size check → IndexedDB Blob → object URL preview`。照片仅本地文件选择，不发送网络请求；替换或删除时清理旧预览 URL。相机不可用时仍能选相册。

## 页面与场景

首页以成品和四阶段纵览为主。详情页四部分始终可切换；烹饪部分有“完整演示”和“跟着做”两种视图。完整演示约 40 秒，依次播放备菜、炒蛋、炒番茄、合炒和装盘的代表性动作；与真实操作计时独立。跟做视图一次聚焦一节点，并固定显示阶段路径、节点跳转、当前用量、火力、参考时间、完成标志和下一步。

## 兼容与取舍

首版以现代 iOS Safari / Android Chrome 为目标。静态网页可部署在支持 SPA 回退的主机。IndexedDB 适合照片 Blob，但浏览器可能清除数据，因此在成品页解释保存范围并处理写入失败。合成原型 PNG 仅供视觉比对，不直接用作可交互界面；真正的步骤动作需要可控制的 SVG 图层。

## 回退

若动画复杂度妨碍功能完整性，先保留每个节点的清楚静态关键帧与文字，再逐一增强动效；不牺牲用量、步骤、计时和照片的正确性。
