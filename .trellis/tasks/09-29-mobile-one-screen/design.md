# 技术设计：手机一屏布局与动作画面

## 页面结构

本地提交 `0880a4a` 已实现一屏外壳、紧凑步骤栏和照片区滚动；以下为复核与补齐时遵循的结构。

- `src/App.tsx` 保持现有状态与数据接口。页面使用视口高度布局：固定头部、四阶段导航、可压缩内容区、底部主操作。每阶段只让需要连续阅读的局部区域滚动。
- 步骤栏改为单行紧凑节点：号码/完成状态直接承载点击，当前步骤标题在相邻标题区显示；小屏可横向滚动节点行，但不增加纵向高度。保留 `inspect` 与 `continue-from-inspected` 的明确区别。
- 食材数据用紧凑分组与并列量值，优先露出主食材和调料；溢出由食材列表局部滚动。成品照片记录区局部纵向滚动，确保上传操作可触达。
- 以 CSS `dvh`、安全区和 `min-height: 0` 处理手机浏览器工具栏变化。避免为了塞入一屏把字缩到难读或把点击目标做得太小。

## 动画方案与取舍

| 方案 | 可行性 | 结论 |
| --- | --- | --- |
| 现有 SVG 图形增加位移/摇晃 | 技术简单，但画面本身像占位图，动作也缺少状态变化 | 不继续叠加装饰动画 |
| 统一画风的 SVG 分层/关键姿势 | 可直接控制暂停、重播与静态降级；适合倒、翻、回锅等烹饪动作 | 烹饪阶段首选，先做一组试作校验画风和动作辨识度 |
| 手绘抽帧精灵图 + CSS `steps()` | 浏览器原生可行，但各帧必须同构图并由同一素材体系绘制 | 动作变化较大时采用；素材质量是前提 |
| Rough.js / Lottie 运行时 | Rough.js 提供手绘线条；Lottie 负责播放现成动画，两者均不会自动产出优质食材画面 | 本轮不为画风问题引入额外运行时 |
| 静态插画 | 没有动作时信息更直接且节省屏幕 | 首页、食材、备菜、成品采用；烹饪动作试作失败时作为回退 |

首页、食材、备菜、成品的场景全部静止；食材页用番茄、鸡蛋静态插画，不继续展示砧板、锅具或假的“备齐”动效。备菜图呈现处理前后或完成姿势，但不播放切/打动作。只有烹饪场景遵循“每个动效要解释一个烹饪变化”，例如蛋液凝固、番茄下锅、回锅翻匀。优先小幅度、可辨识的姿势变化。`prefers-reduced-motion` 显示关键静态姿势。烹饪演示模式沿用既有暂停/重播接口。

## 数据与兼容

- 不修改 `src/progress.ts` 的查看/完成/计时状态机，不修改 `src/photo.ts` 的 IndexedDB 格式。
- 图像资产若新增，放在本地项目中，离线可用。避免远程图片和运行时生成。
- 旧 SVG 场景在过渡中作为静态回退；只有新画面通过手机视觉验收后替换对应场景。

## 依据

- Rough.js 支持带手绘感的 SVG/Canvas 基础图形，但需要自行设计内容：https://roughjs.com/
- CSS `steps()` 可把动画分成离散帧：https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/steps
- CSS 精灵图可通过 `background-position` 选择帧：https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Images/Implementing_image_sprites
- dotLottie 播放器负责播放现成 Lottie 资产及控制，不负责创作画面：https://docs.lottiefiles.com/en/runtimes/distributions/js/v0.x
