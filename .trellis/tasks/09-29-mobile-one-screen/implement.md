# 实施计划

1. 对照 `docs/superpowers/prototypes/tomato-egg/` 六张原型逐屏记录结构、配色、字号、插画比例和交互控件；剔除设备外框/系统状态栏。复核 390 × 844、375 × 667 的现有页面与溢出。
2. 建立原型对应的样式基准，重排首页与四阶段页面。步骤导航分别匹配备菜胶囊与烹饪节点，保持状态、点击范围和局部滚动。
3. 为六个视图准备与原型构图、线条和上色一致的静态插画资产；`src/assets/tomato-egg-hero.webp` 可作候选，但差异明显时按原型重做。确保插画主体不被裁切或按钮遮挡。
4. 移除所有场景循环动画及暂停/重播控件；完整演示改为手动切换静态分镜，烹饪跟做按步骤显示静态姿势。切换必须即时且不修改跟做进度或倒计时。
5. 调整成品阶段记录区上下滑动与照片操作的可达性；保证键盘、触摸和减少动态效果设置可用。
6. 验证：`npm run lint`、`npm run typecheck`、`npm run build`、`npm run test`；在两个视口对照六张原型截图，检查全部静态场景、手动分镜、节点跳转、计时及照片操作。
7. 检查改动范围和 staged diff；每个完成且验证过的逻辑变更分别本地提交，不推送。

## 风险与回退点

- 375 × 667 上食材总量与步骤详情可能无法同时全部常显：保留关键操作，允许明确标示的内部滚动，禁止让页面整体变成长卷轴。
- 原型图包含设备外框和系统状态栏，截图对照时只比较网页内容区域；配方或倒计时数字以现有模型为准，避免视觉复刻导致数据错误。
- 调整页面容器时注意照片 IndexedDB 错误提示、计时控件与底部按钮不能被遮盖。
