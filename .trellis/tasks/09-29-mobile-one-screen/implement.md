1. 复核提交 `0880a4a` 在 390 × 844、375 × 667 的首页和四阶段效果；仅修复剩余溢出、遮挡或不可触达的问题。
2. 检查已有紧凑步骤导航的状态、点击范围和局部滚动，必要时微调 `src/App.tsx` 与 `src/styles.css`。
3. 首页以 `src/assets/tomato-egg-hero.webp` 替换现有成品 SVG，检查完整菜肴不被画框或徽章裁切。让食材、备菜、成品场景全部静止，移除这些场景的暂停/重播控件；食材页改成紧凑的番茄与鸡蛋插画，备菜图展示处理结果。
4. 仅在烹饪阶段试作统一画风的关键帧或分层 SVG 动作。若动作不够清晰，切换为静态关键姿势并记录原因；烹饪场景保留暂停、重播与减少动态效果降级。
5. 调整成品阶段记录区上下滑动与照片操作的可达性；保证键盘、触摸和减少动态效果设置可用。
6. 验证：`npm run lint`、`npm run typecheck`、`npm run build`、`npm run test`；手机浏览器检查两个视口下五个页面状态、静态场景、烹饪演示、节点跳转、计时及照片操作。
7. 检查改动范围和 staged diff；每个完成且验证过的逻辑变更分别本地提交，不推送。

## 风险与回退点

- 375 × 667 上食材总量与步骤详情可能无法同时全部常显：保留关键操作，允许明确标示的内部滚动，禁止让页面整体变成长卷轴。
- 逐帧素材若姿势或画风不一致，优先保留清楚的静态关键姿势，不以低质量动效充数。
- 调整页面容器时注意照片 IndexedDB 错误提示、计时控件与底部按钮不能被遮盖。
